Section 1

What happens when 1,000 tasks
fight for the same memory?

A data center runs hundreds of workloads simultaneously. Each task needs memory, but fast DRAM is limited. When too many tasks get routed to the same memory tier, everything slows down. Watch it happen in real time.

Normal load: 8 tasks
A small cluster with 8 tasks. Classical scheduling (FCFS: first come, first served) assigns them in arrival order. DRAM fills up, remaining tasks go to CXL. Everything works fine. Latency is manageable.
Scale to 100 tasks
Now DRAM is overwhelmed. FCFS has no intelligence, meaning it doesn't know which tasks are memory-sensitive. High-priority tasks get stuck on slow CXL. The red lines appear: congestion, wasted cycles, SLA violations.
Scale to 1,000 tasks
At this scale, even smart greedy heuristics break. There are 2¹⁰⁰⁰ possible assignments, representing more combinations than atoms in the universe. Classical algorithms can only sample a tiny fraction. The data center is gridlocked.
Quantum: all green lanes
RQAOA encodes every task into a quantum state. Through superposition, it explores all possible memory assignments simultaneously. The result: an optimised assignment where sensitive tasks get DRAM and insensitive tasks gracefully use CXL. All green.

Section 2

Why RQAOA? The Quantum Bake-off

We evaluated several quantum algorithms. Most struggle with the datacenter's topology or scale. Step through each algorithm to see exactly why RQAOA emerged as the only viable choice.

1. QAOA (The Baseline)
Step 1 of 4
All 2⁶ possible assignments at once. The quantum state is in superposition.
Can only see nearby nodes. Misses long-range patterns.
2. VQE (The Generalist)
Step 1 of 4
Starts with a random circuit shape (ansatz). It's essentially flying blind.
Circuit shape is a guess. Works for chemistry, not great for scheduling.
3. Quantum Annealing
Step 1 of 4
Start in chaos — high quantum energy. The system is highly excited.
Needs special D-Wave hardware. Connectivity limits mean some pairs can't interact.
4. GM-QAOA (The Heavyweight)
Step 1 of 3
Uses a complex 'mixer' to jump directly between valid memory assignments.
Requires massively complex circuits. Unfeasible on current noisy hardware.
5. RQAOA (The Winner)
Step 1 of 7
1. Superposition: Every task is assigned to both DRAM and CXL simultaneously. The computer is holding all possibilities open.
The problem shrinks every round. Circuit depth stays low and manageable.

Section 3

Enterprise Deployment: The ML Surrogate

Live datacenters cannot wait in cloud queues for a quantum processor. Our solution? Use the quantum computer as a Teacher, and a fast Machine Learning model as the Student.

1. Offline Teacher
We use RQAOA to solve the hardest, most congested scheduling graphs offline, generating mathematically perfect routing data.
2. ML Student
A Graph Neural Network (GNN) is trained on this quantum dataset. It learns to mimic RQAOA's logic without needing quantum hardware.
3. Local Inference
The trained ML model is deployed directly in the datacenter scheduler, making near-optimal routing decisions in under 100 microseconds.

Microsecond Latency

Live QPU calls add massive cloud and queue latency. The ML surrogate makes near-optimal decisions in < 100 microseconds directly in the classical OS.

95%+ Global Optima

While classical Greedy algorithms get trapped in local optima, the ML model (GNN) learns hidden topological correlations from the quantum data to hit the global optimum.

Zero Hardware Lock-in

Runs purely on standard Datacenter hardware. The quantum computer is only used offline, meaning no expensive live dependencies or network failure points.
